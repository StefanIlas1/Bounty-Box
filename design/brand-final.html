07 · Voice

Precise in the product, a little adventurous in marketing.

Inside the app the agent talks like an accountant, an engineer or a procurement officer: numbers first, no hype. Marketing can borrow the bounty-hunter and map-reader voices.

08 · Build screen Next iteration

Requirements are set. The layout comes next.

The final layout is deferred. These are the requirements it must meet, taken from the liked options: shopping cart, log + receipt, single narrative, and code · terminal · cost.

✓

Inspect the code

Every file the agent wrote can be opened and read, along with the terminal output that tested it.

✓

See every decision

Each infra choice shows the requirement it served (users, latency, budget) and the alternatives it beat.

✓

Show the comparisons

Side-by-side test results for every stack tried, including the ones that failed.

✓

Cart at the end

The final stack reads as a cart with one total and one Approve button.

✕

Never expose partner pricing

Show the user's total and why the pick is best. Never show a vendor's discounted partner rate.

✕

Never make a claim that can't be checked

Every "fastest" or "cheapest" links to the sandbox run that measured it. Judges and users will fact-check.
